# v0.5.0 Beta 开源发布判断

日期：2026-10-19。判断对象为本插件目录及其源码发布包。

**结论：可以发布到 GitHub，定位为公开测试版（Beta）。** 当前具备可安装的扩展结构、明确许可证、功能回归、维护说明和已知限制。无需等到覆盖所有模型和长篇剧情，才允许别人查看、试用和改进源码。

本轮固定三分钟、始终空 WAIT 的复现从18次判断降到5次；这是调度复现结果，不是所有真实模型场景都能节省相同比例的承诺。

## 发布时如实说明的范围

验证基线是 SillyTavern 1.19.0 的公开接口与独立夹具。当前没有在真实酒馆页面、所有供应商、上百轮历史、群聊或任意第三方扩展组合中完成全面验收。本版另完成20次真实请求的聚焦复测，发现并修正了构思时的变相追问，摘要见 REAL_MODEL_CHECKS.md。样本数量有限，不是随机对照 A/B，不能据此推算普遍的成功率。

自然等待是可关闭的资源与节奏控制。角色仍可 WAIT、END、STOP，不靠固定心理属性决定性格；强化“给构思留空间”的提示也不是绝对保证，需要完全静止时使用时间暂停。

首次接话的计数口径已经明确：短接话回复不计自主次数；短缓冲结束后由主动模块补发的确认仍计入。长期事实摘要、更广模型适配与更多真实角色试用可作为后续工作。

## 建议的发布方法

1. 将**本插件目录中的文件**作为新仓库根目录，确保根目录直接有 `manifest.json` 和 `index.js`。不要上传整个工作目录或独立测试器的 reports。
2. 保留 MIT LICENSE，作者名暂为 Project 小晴 contributors；可按实际项目署名调整，不捏造仓库地址或贡献者身份。
3. 首次 Release 标题可用“v0.5.0 Beta”，勾选预发布，并附对应安装 ZIP。说明 API 费用、已测范围及反馈方式。
4. 建仓后确认 Actions 运行结果、启用所需的仓库问题反馈或私密漏洞报告设置，再分享仓库安装地址。

目前没有创建远程仓库、上传源码或发布 Release。本判断针对代码和交付内容的准备程度，不等于官方收录或认证。

## 许可与兼容性依据

[GitHub 的许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) 说明公开仓库应明确许可证。项目沿用已有 MIT，未把用户或第三方导入卡片纳入该授权。

[SillyTavern 官方扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/) 对官方内容仓库提出开源许可、文档和最新发行版兼容性要求。自行开源与提交官方内容仓库是不同步骤；后者还需按官方要求验证最新版本。
